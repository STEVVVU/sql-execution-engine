# Same-host hashing comparison

[Run 39738767184](https://github.com/STEVVVU/sql-execution-engine/actions/runs/39738767184), artifact `sql-hyperfine-39738767184`, compares frozen `1f73fcafb08c869f03c1b94cb922222c3c352543` with candidate `fff36c883506c807fe3ce7e943ec319559279832`. The manifest SHA256 is `58a280efdda898ab6eed2598355cc94d3e53eebec351730ddfcb84ee2555b72f`. All 540 invocations passed: 90 excluded warmups and 450 measurements, comprising 90 groups with five repetitions. Every retained CSV was independently checked against the original 15 result digests; all native exits were zero and scratch cleanup passed.

The change reuses the already locked ahash implementation for partition hashing and owned maps. Full scalar-key equality, collision checks, null semantics, row budgets and worker settings remain unchanged. A separate [Callgrind run 39732211058](https://github.com/STEVVVU/sql-execution-engine/actions/runs/39732211058) found 66,833,400 inclusive instructions (15.0% of the custom-four-worker total) in serial partitioning on the frozen 100k-row join, including scalar extraction. That evidence motivated reducing hashing cost; instrumented wall time was excluded. Hashing does not eliminate scalar materialization, row gathering or serial stages.

Both optimized release binaries ran on the same Ubuntu 24.04 VM: Intel Xeon 6973P-C, two physical cores/four logical CPUs, 16,759,304,192 bytes RAM, Linux 7.0.0-1017-azure, Rust/Cargo 1.99.1, Hyperfine 2.0.0, `CARGO_INCREMENTAL=0`. Baseline and candidate built separately in 4m48s and 4m47s. The original disk CSV formula, SQL, result hashes, batch size 8192, custom one/four workers and tuned DataFusion four target partitions are frozen in `scripts/frozen-benchmark.json` (SHA256 `27106d302d96b644dbc3cf68f9f01eaaf904e9ec099e527b8db6f4c77e895ef8`). After one excluded warmup per arm, five rounds reverse the six build/executor arms. Hyperfine owns timing via `--shell=none --runs 1 --warmup 0 --metrics time_wall_clock`; its schema-2 raw measurements were audited. An explicit shell exec, GNU time, startup, CSV decoding, planning, execution and output writes are included equally. OS caches are warm. Each command has a 240s bound, output is at most 1MiB, the driver requires a 10GiB disk reserve, and the unchanged custom engine retains its 1m-row/256MiB-file caps. There is no spill or imposed memory limit. These are whole CLI measurements, not isolated operator timings.

The 1m-row join median falls 8.1% with one custom worker and 9.5% with four. Four custom workers still take 1.94 times the candidate one-worker wall time and 16.5 times the candidate DataFusion wall time. The 1m-row selective query has worse custom medians with overlapping ranges; top-k is effectively unchanged. No general superiority or parallel scaling is established.

Reproduce with the manual [comparison workflow](../../.github/workflows/compare.yml). It runs formatting and the maintained real-product verifier before measuring, archives the frozen baseline, uses independent Cargo target directories, and rejects identical binaries or dependency/profile mismatches before any timed sample. The exact driver command is `python3 scripts/compare.py --baseline-binary /path/to/baseline --baseline-source /path/to/baseline-source --baseline-archive /path/to/baseline.tar --candidate-binary /path/to/candidate --output evidence/compare` after those builds and installation of the checksum-pinned Hyperfine asset.
